## Phase 1 — The 4 feature bug fixes

### 1a. Events Edit silently drops `type`
**Root cause:** `event.resolver.ts:322` does `this.eventRepo.update(id, input)` passing input through. Input has `type`, column is `eventType` → silently ignored. Create works (line 289 maps `eventType: input.type`); update doesn't.
**Fix** `apps/api/src/graphql/resolvers/event.resolver.ts:316-336`: destructure `{ type, ...rest } = input`, build patch, `if (type !== undefined) patch.eventType = type`, then `update(id, patch)`.
**Also** `apps/web/src/app/dashboard/operations/modals/add-event-modal.tsx:41-46`: extend `EVENT_TYPES` to the full user-selectable enum set (add TRAINING, SOCIAL; keep MEETING/WORKSHOP/CONFERENCE/OTHER) so the enum default `MEETING_ROOM` isn't the only unselectable one.

### 1b. Meeting Room Edit/View Details open blank
**Root cause:** `displayRooms` mapper (`meeting-room/page.tsx:235-241`) keeps only `id,name,capacity,status` → discards `centerId,floorId,roomType,hourlyRate,amenities`. Edit modal prefills fall back to defaults; View Details always shows "Not set".
**Fix** `apps/web/src/app/dashboard/operations/meeting-room/page.tsx`:
- Extend `RoomCard` type (lines 36-42) to include `centerId, floorId, roomType, hourlyRate, amenities`.
- Fix `displayRooms` (lines 235-241) to pass them through from the `MEETING_ROOMS` query (which already fetches them).
**Also** small wins in same file: (1) `booked`-status card button has no handler — add a branch in the `RoomCard` click handler (lines 138-141) to open View Details; (2) `book-room-modal.tsx:189-196` add `attendeesCount: attendees` to the `book()` input (state exists at line 43, used only for validation today).
**Deferred** (file beads issue, not this session): "Extend creates duplicate event" — proper fix needs passing the existing event id to the modal and switching to `useUpdateRoomBooking`; non-breaking, lower priority.

### 1c. Requests: `IT_SUPPORT` not in enum → creation fails
**Root cause:** `RequestType` enum (`user.type.ts:68-77`) = `PRINTER, UPGRADE, SERVICES, EVENTS, MAINTENANCE, CLEANING, SECURITY, OTHER`. No `IT_SUPPORT`. Modal offers it → backend enum validation rejects.
**Fix** `apps/web/src/app/dashboard/operations/modals/add-request-modal.tsx:21-26`: replace options with valid enum values — `MAINTENANCE, CLEANING, SECURITY, UPGRADE, OTHER`.
**Also align** `request/page.tsx:200` category filter + `pending-approvals-modal.tsx:30,166` to the same valid set.

### 1d. Inventory Add Space sends `number`, schema requires `name` → creation fails (2 flows)
**Root cause:** `CreateSeatInput.name` is `@IsNotEmpty()` required (`center.input.ts:248-251`). `table-view/page.tsx:~311` and `set-up-center-modal.tsx:~242` send `number` instead → validation fails.
**Fix:**
- `apps/web/src/app/dashboard/inventory/table-view/page.tsx`: change the createSeat input key `number` → `name`.
- `apps/web/src/components/ui/dashboard/set-up-center-modal.tsx:~242`: same `number` → `name`; also add `MEETING_ROOM` to the `SeatType` union (line 22) so the center wizard can create meeting rooms.
- `apps/web/src/lib/apollo/operations.ts:1545-1546`: fix the misleading comment.

## Phase 2 — Auth plumbing (unblocks Phase 3)

**Fix** `apps/api/src/graphql/graphql.config.ts:71-74` context function: before returning, extract Bearer token from `req.headers.authorization`, verify with `jsonwebtoken` using `process.env.JWT_SECRET` (same fallback as `jwt.strategy.ts:37`), and on success set `req.user = { id: payload.sub, email: payload.email, role: payload.role, sessionId: payload.sid }` — exactly matching `JwtStrategy.validate` output (jwt.strategy.ts:46-51).
- **No token / invalid / expired** → leave `req.user` undefined (non-blocking: resolvers that don't read user are unaffected; resolvers that do will 401 cleanly instead of always-401).
- Use lazy `require('jsonwebtoken')` to avoid circular deps (mirrors the lazy requires already used at lines 172-179).
- This is the **only** backend change in Phase 2; no guards added, no middleware, philosophy preserved.

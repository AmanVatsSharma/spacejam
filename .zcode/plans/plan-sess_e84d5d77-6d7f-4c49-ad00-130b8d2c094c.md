## Phase 1, Milestone 1 — Auth Foundation (Enterprise core, part 1 of 4)

Per your decisions: enterprise core first; OTP login necessarily in scope (employees must log in); dev-bypass now with a clean provider hook for later; employees DO log in via OTP. M1 unblocks M2 (Plans+Subscriptions), M3 (allocation+billing), M4 (mobile/web wiring) — each gets its own plan cycle after.

### Step 1 — API: role enum + entity extensions
- Add `EMPLOYEE`, `COMPANY_ADMIN` to `UserRole` in `apps/api/src/graphql/types/user.type.ts`.
- Add `userId?: string | null` FK + `user?` relation to `CustomerEmployee` (`apps/api/src/typeorm/entities/customer-employee.entity.ts`), mirroring the existing `Customer.userId` lazy-provision pattern. (This is the linkage your "employees log in" decision requires.)

### Step 2 — API: OTP table + migration
- New entity `OtpRequest` (`apps/api/src/typeorm/entities/otp-request.entity.ts`): `id, phone, codeHash, expiresAt, consumedAt, attempts, createdAt`.
- Migration `20260809000000-AddOtpAndEmployeeUser.ts`. Prod is PG <11 and runs `synchronize:false`, so the migration must use `CREATE TABLE IF NOT EXISTS` / `ADD COLUMN IF NOT EXISTS` style (consistent with the existing migration conventions).

### Step 3 — API: OTP service + resolver
- `apps/api/src/auth/services/otp.service.ts`:
  - `requestOtp(phone)` — validate phone, rate-limit (≤5 / 15 min / phone), generate 6-digit code, hash with bcryptjs, persist. When `OTP_DEV_BYPASS=true` (server env), return a fixed dev code without sending SMS. SMS send is a single swappable `SmsProvider.send()` call (logs to console until a real provider is configured).
  - `verifyOtp(phone, code)` — match hash, enforce expiry + max attempts, mark consumed, then `findOrProvisionUserByPhone(phone)`, then issue access/refresh tokens via the existing `auth.service.issueTokensFor`.
  - `findOrProvisionUserByPhone`: existing `User` by phone → use; else `CustomerEmployee` match → provision `EMPLOYEE` User (synthetic email `${digits}@phone.spacejam` to satisfy unique-email constraint), link `employee.userId`, set `joinedAt`; else `Customer` contact-phone match → provision `COMPANY_ADMIN`, link `Customer.userId`; else create `MEMBER` (walk-in). Reject `User.active=false`.
- Add `requestOtp` / `verifyOtp` mutations to `auth.resolver.ts` (public, no `@UseGuards`).
- Verify the `id` vs `sub` JWT-payload consistency the audit flagged, so `context.req.user.id` resolves correctly for the new login path.

### Step 4 — Mobile: kill the open-OTP hole, wire real API
- `apps/mobile/src/lib/apollo/operations.ts`: add `REQUEST_OTP_MUTATION`, `VERIFY_OTP_MUTATION` (replacing the synthesized-email `SIGNIN_MUTATION` + `VERIFY_TWO_FACTOR_MUTATION` hack).
- `apps/mobile/src/screens/LoginScreen.tsx`: **delete the `DEV_ANY_OTP = true` constant**. Prod path: `requestOtp(phone)` → `verifyOtp(phone, code)` → store real tokens → `GET_ME` hydrates. Dev-only (`__DEV__`): a shortcut that still calls the same API using the server's dev-bypass code, so dev sessions receive real, working tokens (this also fixes the current fake-token breakage). **No client-side bypass in release builds.**

### Step 5 — Verify
- `pnpm nx test api` for the OTP service/resolver (happy path, expired, wrong code, employee provisioning, suspended-user rejection).
- `pnpm nx typecheck api`.
- Grep to confirm `DEV_ANY_OTP` is gone and no release-path client bypass remains.
- Manual smoke (dev, `OTP_DEV_BYPASS=true`): requestOtp returns dev code → verifyOtp issues token → `GET_ME` returns the user.

### Out of scope for M1 (later milestones)

- Plan / Subscription / billing chain (M2, M3).
- Mobile role-based routing + web admin UI for plans/billing (M4).
- Real SMS provider keys (provider hook left; dev bypass is server-side env only).
